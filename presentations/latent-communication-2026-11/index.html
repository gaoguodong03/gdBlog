BEYOND TOKENS / THREE-AXIS MAP本周研究汇报 · 2026.11.09

综述地图：定位潜隐通信接口

同一种“传向量”方法，可能在传递对象、接口位置与接收方式上完全不同

WHAT · 传递对象

Embedding 是输入端向量。
Hidden state 是某层计算后的状态。
KV cache 是所有注意力层保存的工作记忆。

决定通信载荷到底代表文本、局部状态，还是完整注意力上下文。

WHICH · 接口位置

从哪里取：最后层 hidden，还是每层 KV。
写到哪里：B 的输入端，还是 B 的每层 cache。
如何对齐：同骨干直接对应，异构模型需要翻译。

维度相同不等于语义可读，取出层和注入层必须同时说明。

HOW · Receiver 使用方式

Prefix injection：把 slots 放入 B 输入序列。
Cache fusion：将 A 的信息写入 B 的 KV。
Attention read：B 按当前位置查询外部 memory。

决定 B 是重读摘要，还是在内部工作记忆层直接继续计算。

C2C / CACHE-TO-CACHE FUSION本周研究汇报 · 2026.11.09

C2C：Cache-to-Cache Fusion

Tianyu Fu 等 · 以可训练 fuser 将 source cache 融入 receiver cache

流程

01 · 并行预填充
源模型对输入 X 预填充 · 生成源 KV 缓存
接收模型对输入 X 预填充 · 生成接收端 KV 缓存
↓
词元与层对齐匹配 tokenizer 位置与 Transformer 层
↓
缓存融合器投影、注意力头调制与层门控
↓
接收模型解码基于更新后的 KV 缓存生成答案
KV_B' = KV_B + F(KV_A, KV_B)

C2C 的设定是两个不同模型都对同一输入做预填充，因此各自得到一份 KV cache。接着，它先做词元和层级对齐，再通过一个可训练的缓存融合器，同时读取源模型和接收模型的 KV，把融合结果写回接收模型的工作记忆，最后由接收模型继续解码。

它的重点不在于训练整个模型，而是冻结两端模型，只训练这个 fuser。可以把它理解为：学习一个跨模型的状态翻译和融合接口。

论文方法与结果

Trainable part：冻结 source、receiver，只训练 fuser；用 receiver 的 next-token loss 监督。

数据：OpenHermes 2.5 前 50 万条样本，训练 1 epoch。

LATENTMAS / LATENT REASONING AND KV HANDOFF本周研究汇报 · 2026.11.09

LatentMAS：Latent Reasoning 与 KV Handoff

Jiaru Zou 等 · 同一模型骨干在不同角色之间传递完整工作记忆

流程

01 · 跨 Agent KV 交接
规划者读取任务 · latent 推理
→
审查者接收全层 KV · 继续推理
→
修订者接收累积 KV · 修订状态
→
求解者接收工作记忆 · 生成答案
02 · Agent 内部 latent 推理步
最后一层隐状态当前连续状态
↓
对齐 Wₐ映射回输入 embedding 空间
↓
下一 latent 推理步继续前向计算 · 增加新的 KV

上半部分是角色间的全层 KV 交接；下半部分是单个角色内部生成 latent thought 的循环。

论文方法与结果

Core idea：中间角色不把推理 decode 成文本，而是直接交接 KV 工作记忆。

Alignment：Wₐ 由 embedding 权重计算，模型不通过任务监督训练。

GSM8K accuracy，作者报告。14B 条件下输出 token 从 TextMAS 的 3324 降至 LatentMAS 的 644。

工作证明：在共享模型骨干的前提下，完整 KV 工作记忆可以作为角色协作的交接载体；但它仍然传递长 KV，没有解决固定带宽下如何压缩的问题。

方法定位同骨干下的连续工作记忆接力。它不把长 KV 压成固定少量 slots。

LatCom：Cross-Agent Latent Compression

Shinan Zhang 等 · 用 task-grounded compressor 将多份 latent trajectory 汇总为固定 receiver-readable slots

流程

01 · 专业发送端
数学发送端40 步 latent 推理
科学发送端40 步 latent 推理
代码发送端40 步 latent 推理

↓

LatCom 压缩的是多个发送端的 latent 轨迹，并非先分别压缩、再拼接。

Two-stage training：先训练 single-sender readability，再训练 multi-sender fusion。

监督：冻结 sender 与 receiver，仅训练 compressor；使用 receiver 端生成损失、对比项与对齐项。

对齐实验：有限私有事实可以传递

测试组对齐后原生 embedding
已见键的新配对126 / 128128 / 128

已见键的新配对：键字符串在训练中见过，只更换键与私有值的配对。新键 / 已见 token：完整键首次出现，但每个 token 都被对齐器训练覆盖；“含未见 token”则至少含一个未被训练覆盖的 token。

原生 embedding 是直接给 B 正确输入向量的上限对照；对齐后是将 A 的 hidden 映射成该向量。略低于上限说明映射仍有误差，但 B 已能使用 A 的状态。

每组由 32 个底层实例衍生，不能把 128 题视为独立样本。

压缩实验：训练可运行，信息利用未建立

指标结果
验证 NLL（保留集 token 损失）2.815 → 0.826
缺失信息完整答案（下游任务 EM）0 / 192
缺失代码位置正确1 / 256
8-slot 模块492,032 参数，300 steps

NLL 衡量保留集上预测 token 的损失下降，不等于任务完成。完整答案采用严格精确匹配；代码位置正确衡量缺失关键信息是否在指定位置被恢复。

在本私有事实任务中，完整答案正确就是下游任务成功，因此当前为 0 / 192。其他任务可不复原原文仍成功，必须另报端到端任务成功率。

原生文本控制存在续写与停止问题，不能将全部失败只归因于压缩。

本周结论同底座下，对齐后的连续表示具有可传递性；当前 8-slot 小压缩器没有建立可靠的 receiver-readable 信息接口。
