怎么让内网服务支持外网访问？以 Tailscale Funnel 为例

发表于2026-11-25|更新于2026-11-25|果冻的科普专区
|总字数:1k|阅读时长:3分钟

我把「书童四九」部署在一台 miniPC 上。在内网打开应用的 8100 端口，就能看到登录页。可要是想让朋友在家里也打开这个页面，该去哪里配？是去 1Panel 加个网站，还是在服务里加个设置？如果服务跑在 K8s 里，又该在哪一层接入？

这次我用的是 Tailscale Funnel。四九仍然跑在 miniPC 上，朋友在普通浏览器里打开一个 HTTPS 地址，请求经 Tailscale 转回 miniPC，再交给四九。

一张图看清请求怎么走

服务就是用户最终要访问的应用。四九负责显示登录页、验证账号和处理聊天请求。它以容器运行，Docker Compose 在 miniPC 上把应用入口映射到了 8100 端口。

1Panel 是服务器的管理后台。管理员登录 1Panel，可以部署和重启容器、查看日志。图上实线是访客打开四九时走的路径，虚线是管理员通过 1Panel 管理应用部署的关系。1Panel 项目

K8s 是 Kubernetes 的简称，负责部署和管理集群里的容器应用。应用跑在 Pod 里，名为 Service 的 K8s 资源给这些 Pod 提供稳定的访问入口。四九这次采用的是 1Panel 管理的 Docker Compose 部署。图里的 K8s 接法适用于应用已经部署在集群里的情况。Kubernetes Service 文档

Tailscale 怎么把请求送进内网？

Tailscale 可以把设备接入同一个私有网络，叫 tailnet。如果访问者都是自己人，可以让他们的设备加入 tailnet，再通过 Tailscale Serve 把应用共享给有权限的设备。这适合自己远程访问，或者给小团队使用。Tailscale Serve 文档

我希望朋友只用浏览器就能打开四九，于是用了 Funnel。访问者打开 https://设备名.网络名.ts.net，浏览器先连到 Tailscale 的公网中继。中继把连接送给 miniPC 上的 Tailscale 节点，再由节点把请求交给配置好的应用地址。这条链路可以在家用宽带没有公网 IP 的情况下工作，也省去了在路由器上给四九配置入站端口映射的步骤。Funnel 使用 Tailscale 提供的 .ts.net 域名。Tailscale Funnel 文档

真正要配的是这四个地方

  1. 在服务所在环境里部署应用。 四九跑在 miniPC 的 Docker Compose 里，先确认 miniPC 上的 Funnel 节点能够访问四九的 8100 端口。这才是公网入口后面要接的应用地址。
  2. 在能访问应用的机器上布置 Tailscale 节点。 我把四九专用节点 st49-public 放在同一台 miniPC 上，并设置随主机启动。节点也可以放在另一台机器上，前提是它能访问应用入口。
  3. 在 Tailscale 管理后台确认权限，再回到节点开启 Funnel。 先让节点加入自己的 tailnet，确认 MagicDNS 和 HTTPS 证书可用，再用访问策略允许这台设备使用 Funnel。四九用设备标签把权限授给专用节点。节点出现在设备列表，表示它已经入网。接着在节点上启用 Funnel，指向第一步确认的应用地址，生成的 .ts.net 地址才会接到四九。Funnel 的前提和访问策略
  4. 在应用里定好访问规则，再从外网验证。 四九允许访客打开登录页，聊天由四九账号控制，登记新账号由管理员处理。上线时，从外网确认 HTTPS 登录页能打开，也验证了自助注册提交会被拒绝。

如果应用部署在 K8s，要改的是 Funnel 的转发目标。比如把 Tailscale 节点放在集群外，通过节点可访问的 Ingress 入口接入。Ingress 控制器接到请求后，根据域名和路径把请求交给对应的 Kubernetes Service，再由 Service 把流量送到应用 Pod。这样 Pod 重建后，Funnel 依然可以使用同一个入口。Kubernetes Ingress 文档
