Codex 博客发布流程跑通测试

发表于2026-05-30|更新于2026-05-30|果冻的航海日志
|总字数:455|阅读时长:1分钟

这是一篇由 Codex 在本地博客仓库中创建、生成并部署的流程测试文章。

这次测试的目的很简单：确认以后我在 Codex 里产生一个选题之后，可以直接完成从写作到上线的完整链路，而不是只停留在本地草稿。

这次要跑通什么

这条链路包含四个动作：

  1. 在 source/_posts 下创建 Markdown 文章。
  2. 补齐 Hexo 需要的 Front Matter。
  3. 运行本地生成命令，确认站点可以正常构建。
  4. 执行部署脚本，把生成结果推到线上博客。

如果你正在网页上看到这篇文章，说明这条 Codex 写作发布链路已经至少跑通了一次。

图片链路测试

封面图这次不再复用已有 logoHexo.jpg，而是把网上找到的 GitHub Pages SVG 图标保存到 source/img/logoGithubPages.svg，再通过 cover: ./img/logoGithubPages.svg 引用。这验证了“从网上找封面图、放入 source/img、Front Matter 使用相对路径”的流程。

正文图片则按我平时 PicGo 上传后的图床格式引用：

这里验证的是 Hexo 对 PicGo 外链图片的渲染路径。以后正式写文章时，正文截图、流程图、论文插图优先用 PicGo 上传后的 Markdown 图片链接，而不是把大量正文图片塞进 source/img。

以后怎么用

后续遇到值得记录的内容，可以直接把想法、链接、截图或一句话主题丢给 Codex。Codex 负责整理结构、写成文章、放到正确目录，并在你确认要发布时执行部署。

这篇文章本身没有长期内容价值，它的价值是作为一枚路标：从这里开始，博客写作可以进入更自动化的工作流。
